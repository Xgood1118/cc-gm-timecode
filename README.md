# 时间码换算与丢帧处理

一个能正确处理 drop-frame 与普通时间码互转的换算器。纯 Python 标准库，
无第三方依赖。

## 保留签名

- `parse_tc(text, fps)` — 解析时间码字符串，返回 `TC(hours, minutes, seconds, frames, drop)`
- `format_tc(frames, fps)` — 由 `TC` 或总帧号生成时间码字符串
- `to_frames(tc, fps)` — 时间码（`TC` 或字符串）转总帧号
- `from_frames(n, fps)` — 总帧号转 `TC`

## 新增接口

- `tc_from_frames(frames, fps)` / `frames_from_tc(text, fps)` — 帧号 ↔ 时间码字符串
- `convert_tc(text, from_fps, to_fps)` — 两种帧率间换算时间码（保持帧号不变）
- `concat_segments(segments)` — 多帧率片段首尾拼接
- `align_to_reference(tc_text, fps, ref_seconds, tol_frames=2)` — 外部时基对齐
- `day_frames(fps)` / `nominal_fps(fps)` — 一天帧数 / 名义帧率
- `TimecodeError(ValueError)` — 携带 `field`（出错字段名）与 `position`
  （1 基字符位置）；`SegmentError(ValueError)` — 拼接参数错误

## 换算规则

- **29.97 fps（丢帧 / drop-frame）**：名义帧率 30，帧号分隔符 `;`。除整十分
  （分钟数为 10 的倍数）外，每分钟跳过帧号 00、01（共 2 帧）。一天共
  **2589408** 帧。帧号公式：
  `frames = ((h*60+m)*60+s)*30 + f − 2*(总分钟数 − 总分钟数//10)`；
  反向按 10 分钟循环（17982 帧 = 18000 − 18）还原，往返无损。
- **23.976 fps**：按名义帧率 **24** 处理，非丢帧，分隔符 `:`。
- **25 fps**：名义帧率 25，非丢帧。
- **24 / 30 fps**：按给定帧率，非丢帧。
- **其他 fps**：按 `round(fps)` 的名义帧率处理，非丢帧。
- **23.976 与 25 之间换算**：各自按**名义帧率**（24 / 25）独立做
  “时间码 ↔ 帧号”换算，不做 1000/1001 速率校正。`convert_tc` **保持帧号
  不变、按目标帧率重新分段**，例如 `convert_tc("00:00:01:00", 23.976, 25)
  == "00:00:00:24"`（24 帧在 25 fps 下是 0 秒第 24 帧）。

## 校验规则

非法时间码抛出 `TimecodeError`（`ValueError` 子类），错误信息里写明出错字段
及该字段起始的字符位置：

- 小时位越界（24 小时制，应取 0–23）
- 分钟位 / 秒位越界（应取 0–59）
- 帧位越界（应取 0 到名义帧率 − 1）
- **丢帧位不存在**：非整十分的 `MM:00;00`、`MM:00;01` 在丢帧模式下被跳过
  （`00:00:00;00`、`00:00:00;01` 属于整十分，合法存在）
- 分隔符 `;` 仅适用于 29.97
- 格式错误 / 空输入（`None`、`""`、纯空白都确定性地报错）

## 边界

- 一天按 **24 小时**回绕：`from_frames` 对一天帧数取模，29.97 下第
  2589408 帧回到 `00:00:00;00`，`-1` 回绕到 `23:59:59;29`，**不产生负帧号**。
- 空输入确定性地抛出 `ValueError("空输入：...")`。
- 单帧输入：`00:00:00;00` → 0；裸数字串（如 `"1800"`）按总帧数处理。

## 多帧率拼接

`concat_segments(segments)` 的每段是 `{"fps": ..., "frames": 段帧数}`，返回：

| 键 | 含义 |
|---|---|
| `total_frames` | 所有段帧数之和（单调递增，不回绕） |
| `starts` | 每段起始的总帧号（按段帧数累加，严格递增） |
| `boundaries` | 内部拼接点（第 i 段末帧 + 1 == 第 i+1 段首帧） |
| `start_tc` / `end_tc` | 每段按**该段帧率**换算的起止时间码（24h 回绕） |
| `day_index` | 每段起始所在天数（按该段一天帧数计算） |
| `segments` | 逐段明细（index/fps/frames/start/end/时间码/day_index） |

拼接后总帧号连续，段边界不丢帧、不重帧；段内一律沿用该段自己的规则
（29.97 段用丢帧、其余段用非丢帧）。

**跨午夜**：`starts` / `total_frames` 继续递增不回绕，只有各段时间码按 24 小时
回绕，因此不会出现负帧号。
`day_frames(25) = 2160000`，所以 25 fps 下 `[{..., 2159990}, {..., 20}]`
的 `starts == [0, 2159990]`，第二段 `start_tc == "23:59:59:15"`，`end_tc`
回绕为 `"00:00:00:09"`。

## 时基对齐

`align_to_reference(tc_text, fps, ref_seconds, tol_frames=2)` 用**真实帧率**
（29.97 → 30000/1001，23.976 → 24000/1001，其余原样）把外部真实秒换算为帧，
与时间码帧号比较：

- `offset_frames = round(ref_seconds × real_fps) − 时间码帧号`（对齐偏移量）
- `error_frames` = 对齐后残差（帧）
- `aligned_frames` / `aligned_tc` = 施加偏移后的帧号与时间码（24h 回绕）
- `abs(offset_frames) > tol_frames` 时抛出 `TimecodeError("超出容差...")`

## 关键数值

丢帧（29.97）换算：

| 帧号 | 时间码 | 说明 |
|---:|---|---|
| 0 | `00:00:00;00` | 第 0 分 0 秒第 0 帧存在（整十分） |
| 1 | `00:00:00;01` | 第 0 分 0 秒第 1 帧存在（整十分） |
| 1799 | `00:00:59;29` | 第 1 分钟前最后一帧 |
| 1800 | `00:01:00;02` | 跳帧后首个合法帧（`1802 − 2×1 = 1800`） |
| 17982 | `00:10:00;00` | 整十分不丢帧（17982 = 18000 − 2×9） |
| 107892 | `01:00:00;00` | `3600×30 − 2×(60−6)` |
| 2589407 | `23:59:59;29` | 一天最后一帧 |
| 2589408 | `00:00:00;00` | 一天回绕 |
| −1 | `23:59:59;29` | 负帧号回绕，不产生负值 |
