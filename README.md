# 时间码换算与丢帧处理

一个能正确处理 drop-frame 与普通时间码互转的换算器（仅 Python 标准库，无第三方依赖）。

## 保留签名

- `parse_tc(text, fps)` — 解析时间码字符串，返回 `TC(hours, minutes, seconds, frames, drop)`
- `format_tc(frames, fps)` — 由 `TC` 或总帧数生成时间码字符串
- `to_frames(tc, fps)` — 时间码（`TC` 或字符串）转总帧数
- `from_frames(n, fps)` — 总帧数转时间码 `TC`

## 换算规则

- **29.97 fps（丢帧 / drop-frame）**：名义帧率 30，分隔符 `;`。每分钟跳过帧号
  00、01（共 2 帧），但整十分（分钟为 10 的倍数）不跳。一天共 2589408 帧。
  与非丢帧的换算关系：
  `frames = ((h*60+m)*60+s)*30 + f - 2*(总分钟数 - 总分钟数//10)`，
  反向按 10 分钟循环（17982 帧）还原，往返无损。
- **23.976 fps**：按名义帧率 **24** 处理，非丢帧，分隔符 `:`。
- **25 fps**：名义帧率 25，非丢帧，分隔符 `:`。
- **23.976 与 25 之间换算**：各自按名义帧率（24 / 25）独立做
  “时间码 ↔ 帧号”换算，不做 1000/1001 速率校正；跨帧率换算时保持帧号不变，
  即同一帧号在 23.976 下按 24 解释、在 25 下按 25 解释。
- 其他 fps：按 `round(fps)` 的名义帧率处理，非丢帧。

## 校验规则

非法时间码抛出 `ValueError`，并指出错在哪一位：

- 小时位越界（应按 24 小时制取 0–23）
- 分钟位 / 秒位越界（应取 0–59）
- 帧位越界（应取 0 到名义帧率 − 1）
- 丢帧位不存在：非整十分的 `MM:00;00`、`MM:00;01` 在丢帧模式下被跳过
- 丢帧分隔符 `;` 仅适用于 29.97
- 格式错误 / 空输入（空输入确定性地报错）

## 边界

- 一天按 24 小时回绕：`from_frames` 对帧数取一天的模，第 2589408 帧（29.97）
  回到 `00:00:00;00`，`-1` 回绕到 `23:59:59;29`，不产生负帧号。
- 空输入：确定性地抛出 `ValueError("空输入：...")`。
- 单帧输入：`00:00:00;00` 对应帧号 0；裸数字串（如 `"1800"`）按总帧数处理。

## 自测

```
python -m pytest tests -q
python -m timecode.cli data/tc.txt --fps 29.97 --out frames.json
```

测试覆盖：往返无损（含整分钟边界扫描）、整分钟边界精确帧号、非法码报错、
日边界回绕、空输入与单帧输入、23.976/25 名义帧率、同一批输入跑两次结果一致。

## 实测结果（`data/tc.txt` @ 29.97 丢帧）

| 行 | 输入 | 帧号 | 往返结果 | 往返差异 | 说明 |
|---:|---|---:|---|---:|---|
| 1 | `00:00:00;00` | 0 | `00:00:00;00` | 0 | 一天起点 |
| 2 | `00:01:00;02` | 1800 | `00:01:00;02` | 0 | 第 1 分钟首个合法帧（00、01 被丢） |
| 3 | `01:00:00;00` | 107892 | `01:00:00;00` | 0 | 整小时边界 |
| 4 | `23:59:59;29` | 2589407 | `23:59:59;29` | 0 | 一天最后一帧 |
| 5 | `00:99:99;99` | — | — | — | 非法：分钟位越界：99（应取 0-59） |

4 条合法条目往返差异均为 0；1 条非法条目（`00:99:99;99`）报“分钟位越界”。
同一批输入跑两次，`frames.json` 内容逐字节一致。
